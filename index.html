Cybersecurity Club & AI

A student research and engineering group that examines defensive security, AI-system behavior, Linux administration, adversarial methods, and capture-the-flag problem solving through controlled, documented experiments.

Members move from observation to evidence: define a technical question, construct an authorized test environment, collect results, document assumptions, and explain what the evidence does—and does not—support. The objective is durable systems reasoning rather than tool memorization.

  • Compare hypotheses, divide evidence collection, and review conclusions as a team

  • Coordinate roles, checklists, findings, and final technical reporting

Linux & Operating Systems

  • Develop command-line fluency and inspect system state directly
  • Study users, permissions, services, processes, networking, and packages
  • Use repeatable terminal workflows with logs, notes, and verification steps

AI & Emerging Technology

  • Model AI-system assets, trust boundaries, misuse cases, and failure conditions
  • Use AI assistance with source verification, privacy controls, and human review
  • Evaluate emerging systems through technical literature, demonstrations, and critique

Cybersecurity Fundamentals

  • Examine network services, identity, segmentation, and observable traffic behavior

Program architecture

A curriculum organized as an investigative pipeline.

The program progresses from systems models to controlled experimentation, implementation, documentation, and technical review. Each stage produces evidence that can be examined by another student rather than relying on unexplained success.

01

Construct a system model.

Members identify components, data flows, privileges, trust boundaries, and human dependencies across networks, web applications, accounts, operating systems, and AI tools. A useful model predicts where failure can occur and what evidence the failure would produce.

02

Test hypotheses in authorized laboratories.

Testing remains inside CTFs, guided laboratories, sandboxed demonstrations, and explicitly authorized systems. Members record scope, procedure, observations, and limitations so technical ability develops alongside professional judgment.

03

Build instruments and publish methods.

Members create scripts, dashboards, demonstrations, internal references, and technical reports. The deliverable should explain how the result was obtained, what assumptions were made, and how another person could reproduce it.

04

Defend findings through competition and presentation.

Students apply their methods in CTF-style challenges, workshops, project reviews, and presentations. Leadership means improving the team's process, evidence quality, and technical clarity.

Technical tracks

Focused tracks with shared analytical standards.

Each track develops a different technical domain while using the same standards: define the system, control the environment, verify observations, document uncertainty, and communicate results. Beginners and advanced members can work at different depths within that framework.

01

Defensive Security

Threat modeling, identity hardening, phishing analysis, incident triage, privacy controls, and the measurement of whether a defense changes observable risk.

02

Linux and Systems

Command-line fluency, filesystems, permissions, services, networking utilities, package management, shell automation, and the disciplined maintenance of test environments.

03

CTF Operations

Structured problem solving across web security, cryptography, forensics, reverse-engineering concepts, open-source research, and collaborative challenge execution.

04

Web Security Concepts

How web applications move and store data, establish identity, enforce authorization, expose attack surfaces, and produce evidence when controls fail.

05

AI Security

Prompt-injection models, data-exposure risk, evaluation design, automation boundaries, AI-assisted research, and the limits of interpreting model output as evidence.

06

Project Engineering

Club-built demonstrations, internal documentation, small tools, research notes, presentation systems, and student-led technical reviews.

Hot topic

AI systems introduce new interfaces, dependencies, and failure modes.

The club treats an AI system as a technical pipeline with data sources, model behavior, external tools, users, policies, and deployment infrastructure. Security analysis asks where trust is assumed, where information can cross boundaries, and how performance or safety claims can be evaluated.

AI-assisted research

Use AI to accelerate exploration while independently checking sources, calculations, code behavior, and factual claims.

Prompt and data risk

Trace how sensitive information can cross boundaries through prompts, logs, connectors, training data, weak policy, or unreviewed automation.

Security automation

Evaluate how scripts, retrieval systems, and model-assisted workflows affect documentation, triage, learning, and defensive analysis.

Ethical boundaries

All work remains bounded by authorization, privacy, safety, school policy, and the requirement to document limitations honestly.

Responsible technical culture

Technical depth requires stronger controls, not weaker ones.

Cyber Raptors treats scope, authorization, privacy, evidence handling, and disclosure as part of the technical method. A result obtained without these controls is not considered high-quality work.

Can beginners join?

Yes. Beginners are expected to ask precise questions, follow laboratory controls, document their work, and improve through review. Existing expertise is useful but not required.

Is this only about online safety?

No. Digital-safety awareness is one component. The larger program develops systems models, cybersecurity methodology, AI-security analysis, Linux fluency, CTF problem solving, and technical communication.
