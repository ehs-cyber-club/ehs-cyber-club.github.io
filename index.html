Research and technical practice

Different tracks. One standard of evidence.

Beginners and advanced members can work at different depths while following the same operating method: define the system, control the environment, verify observations, document uncertainty, and communicate results.

01

Defensive Security

Threat modeling, identity hardening, phishing analysis, incident triage, privacy controls, and measurable defense.

02

Linux & Systems

Command-line fluency, filesystems, permissions, services, networking utilities, packages, and shell automation.

03

CTF Operations

Structured problem solving across web security, cryptography, forensics, research, and collaborative challenge execution.

04

CyberPatriot

Configuration analysis, system hardening, evidence preservation, role coordination, checklists, and technical reporting.

05

AI Security

Prompt-injection models, data-exposure risk, evaluation design, automation boundaries, and source verification.

06

Project Engineering

Club-built tools, dashboards, demonstrations, internal references, research notes, websites, and student-led review.

Program architecture

An investigative pipeline.

The program moves from a system model to controlled experimentation, implementation, documentation, and technical review. Each stage should produce evidence another student can inspect.

Construct a system model.

Identify components, data flows, privileges, trust boundaries, human dependencies, and the evidence a failure would create.

Test hypotheses in authorized laboratories.

Work inside CTFs, guided labs, sandboxed demonstrations, and explicitly authorized systems while recording scope and procedure.

Build instruments and publish methods.

Create scripts, dashboards, demonstrations, references, and reports that explain assumptions, observations, and limitations.

Defend findings through competition and presentation.

Apply the method in challenges, workshops, project reviews, and briefings. Leadership improves the team’s process and clarity.
